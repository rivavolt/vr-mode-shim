# vr-mode-shim

An LSPosed/Xposed module scoped to the system framework. It declares `android.software.vr.mode` and `android.hardware.vr.high_performance` in SystemConfig as it loads, before ActivityManagerService copies the features into the cache apps read and before PackageManagerService takes the map, so a phone Google never certified (nothing1, for the Daydream View) counts as Daydream-ready. Android 16 also removed `VrManagerService` but kept `Activity.setVrModeEnabled`, whose server side then dereferences the missing `VrManagerInternal` and throws a `NullPointerException` into the app; Daydream's VR launcher and every GVR title call it in `onCreate`, so the hook answers the call with success when no VR manager is registered, and does what VrManagerService did with the request: it binds the VR listener the resumed activity names and tells it which activity that is, unbinding it when the resumed activity no longer asks for VR mode. VR Services learns VR mode is on only from that binding, and its controller service ignores the Daydream button until it does.

Build on volt (x86_64 only, for aapt2): `nix develop -c ./gradlew assembleDebug`, APK at `app/build/outputs/apk/debug/app-debug.apk`. Enable it in Vector with scope `system`, then restart the framework.
